# Notes for AI coding agents (Antigravity, etc.)

ResQWork is a **working** product. Read before changing anything:

- **Run it:** `cd backend && python run.py` (after `pip install -r requirements.txt`) serves the API and the pre-built website at http://localhost:8000. Demo login: `manager@healthcare.demo` / `demo1234`.
- **Tests must stay green:** `cd backend && python -m unittest discover -s tests -t .` (259 tests, 8 skipped without API keys).
- **Website:** source in `frontend/src` (React + Vite + Tailwind). `frontend/dist` is the pre-built copy the backend serves. After editing the source, rebuild with `cd frontend && npm install && npm run build`, or changes won't show on :8000. Use `npm run dev` (port 3000) for hot reload.
- **Do not** replace the scheduling engine, rename backend fields (e.g. `version`), or make soft constraints hard. Hard rules live only in `backend/core/rules.py`.
- **AI never decides:** LLM output is parsed and validated; the solver (`backend/engine/`) makes assignments; a manager approves. Explanations must use solver facts only.
- **Industries are configuration:** `shared/domains/*.json` (generated by `backend/scripts/build_domain_configs.py`), `shared/policies/`, `shared/demo-data/`. No industry-specific `if` statements in engine or UI.
- **Secrets** go in `backend/.env` (see `.env.example`), never in frontend code.
- Docs: `README.md`, `docs/architecture.md`, `docs/api-contract.md`, `docs/demo-script.md`.
- **Next steps:** `docs/REMAINING_PLAN.md` lists what is finished (backend for the full platform spec, 259 tests) and the exact frontend screens still to build, each mapped to an existing API method in `frontend/src/api/client.ts`.
- **Flagship demo (100 staff):** `admin@flagship.demo` / `demo1234` (also `meera@`, `arjun@`, `kavya@`, `rohan@flagship.demo`).
